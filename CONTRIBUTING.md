# Contributing

Thank you for your interest in contributing! 🚀

This project is an open-source learning initiative focused on learning production engineering by building a real-world messaging platform together.

**You don't need to be an expert to contribute.**

## 🎯 Our Approach

We value learning and collaboration over simply getting code merged.

When contributing, we encourage you to:

- Ask questions.
- Explain your reasoning.
- Discuss trade-offs.
- Share alternative approaches.
- Learn from code reviews.
- Write tests.
- Document important decisions.
- Be open to feedback.

A contribution doesn't have to be code.

You can contribute through:

- Code
- Architecture discussions
- Documentation
- Testing
- Bug reports
- Security research
- Product ideas
- UX/design
- Infrastructure
- Code reviews

## 🛠️ Before You Start

For larger changes, please discuss the idea before implementing it.

Depending on the topic, use the appropriate community channel or open an issue.

Examples:

- Product ideas → `#product-feature-ideas`
- Architecture → `#project-architecture`
- Backend → `#project-backend`
- Frontend → `#project-frontend`
- Infrastructure → `#project-infrastructure`
- Security → `#security-research`

## 🔀 Pull Requests

When submitting a pull request:

- Keep the change focused.
- Explain what you changed.
- Explain why you changed it.
- Include tests where appropriate.
- Update documentation when necessary.
- Keep commits understandable.
- Be open to review and discussion.

## 🧪 Testing

Contributions should include appropriate tests whenever practical.

We want testing to be part of the development process rather than something added only at the end.

## 📝 Documentation

If a contribution introduces an important architectural or behavioral decision, document it.

Good documentation is part of the implementation.

## 🤝 Code Review

Code review is a learning opportunity.

Reviewers should focus on:

- Correctness
- Security
- Maintainability
- Performance
- Testing
- Reliability
- Simplicity
- Architectural consistency

Please critique the implementation, not the person.

## 🌱 New Contributors

If you're new to open source or unfamiliar with part of the technology stack, don't hesitate to ask questions.

We want contributors to understand *why* something works, not simply copy an implementation.

## ⚠️ Important

This project is currently evolving.

Architecture, technologies, requirements, and development practices may change as the community learns.

Please check the latest project documentation before starting significant work.

Thank you for helping us learn and build together! 🚀
